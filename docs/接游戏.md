# 接游戏（2026-11-26 起）

演员模型和引擎无关：游戏把一张戏卡（格式见 `戏卡格式.md`，代码里是 card dict，同考卷）交给 `scripts/actor.py`，
拿回整理好的台词；拿到 `None` 就用游戏里手写的台词。**给钱、接任务、改好感等一律由游戏代码做，模型只说话。**

## 调用

```python
from actor import Actor
a = Actor("models/q35-2b-v3-dpo2-s1-mlx4")   # 当前最好；温度 0.3、top_p 0.9、重复惩罚 1.15（只罚自己写的）
a.warm(card)          # NPC 进入视野时：把「系统提示 + 【世界】 + 【说话人】」预读进缓存（约 1 秒，玩家不用等）
res = a.say(card)     # 生成 → 把关；没过就换种子再试一次
res.lines             # [{"name", "emotion", "action", "text"}]；None = 退回，用手写台词
res.reject, res.fixes # 退回原因 / 修过什么（写日志）
```

本机（M 系列 8 GB，dpo2-s1 4 位）实测 6 张卡：有缓存时**首字 0.30–0.46 秒、整段 0.6–1.1 秒**；预读约 1 秒。
缓存按 NPC 存最近 8 个（`cache_npcs`）。同一个 NPC 的【世界】【说话人】要逐字不变才命中缓存，所以：

| 卡里哪一栏 | 放什么 | 会不会变 |
| --- | --- | --- |
| 【说话人】「知道」 | 长期身份知识（职业流程、价目、熟人） | 固定（能缓存） |
| 【对方】「怎么看他」 | 对这个人的看法（关系记忆），游戏按事件改写一句 | 会变 |
| 【场景】「已发生的事」/【前文】 | 近期事件记忆（按相关、新近挑 3–5 条）/ 刚说过的话 | 会变 |
| 【场景】「提得到的」（`scene.at_hand`） | 这会儿看得见 / 想得到的东西（物品标签按 NPC 身份的看法），游戏按距离、显眼、和这场的事相关挑 ≤ 8 条 | 会变 |

「提得到的」是 11-26 新加的一行（模型没训练过），验证见 `lab_note.md` 11-26「素材放【场景】」：素材卷 12 张 × 6 种子，
读者版放【场景】vs 放「知道」+0.12（不显著，不比原来差），用到素材 32% → 57%，个别卡会硬塞（素材离场景越近越爱用）。
1 个标签约 7 token，10 条约多 0.1 秒首字；卡在给模型的条数，不在游戏端查标签。

## 出口把关 `gate(card, raw)`（不依赖模型，可单独用）

| 情况 | 处理 |
| --- | --- |
| 解析不了的行 | 丢掉 |
| 不在「谁能开口」里的人开口（替对方写台词） | 从这一行起整段截掉 |
| 超过最多句数 | 截掉 |
| 「动作：不写」却写了括号 | 删括号；「可以写」时句首括号拆成 `action`，句中括号删 |
| 表情不在清单里 / 写进括号 | 当「平常」/ 删 |
| 超字数 | 在限内最后一个句末标点（没有就逗号）截断；截不了丢整句 |
| 后一句和前面某句 ≥ 6 字一样 | 丢后一句（复读） |
| 「别说漏」≥ 5 字、「不能说」≥ 7 字片段出现在台词里，且卡上公开部分没有（「对外说……」的掩饰说法不算） | **整段退回** |
| 「心里想的」≥ 8 字原话出现，且卡上公开部分没有 | **整段退回** |
| 整理完一句不剩 | 退回 |

量考试输出（`actor.py gate 输出前缀`）：

| 输出 | 段数 | 原样通过 | 修过 | 退回 |
| --- | --- | --- | --- | --- |
| dpo2-s1 @ 0.3 公开卷（3 种子） | 180 | 95% | 5%（超字数 5、删括号 4、截句 1） | 0 |
| dpo2-s1 @ 0.3 专项卷（9 种子） | 135 | 89% | 11%（超字数 13、删括号 5） | 0 |
| dpo2-s1 素材卷（云上，3 种子） | 36 | 94% | 6% | 0 |
| 第 4 批种子 1 素材卷（已知会说漏） | 36 | 86% | 0 | 14%：牙人说出「山背货贩子」3 次、裁缝说出「腰身比去年粗了一圈」2 次，都拦下 |

说漏检查只抓字面一样的；换了说法的说漏（「那家伙替贩私货的拉客」）抓不到，那是模型本身要守的（dpo2-s1 说出口约 1–3%）。
「不能说」门槛 7 字是因为秘密常带着要打听的对象（M08「暗查大昌洋行经理」，台词问「大昌洋行经理昨晚请的是谁」不算漏）。

## 本机服务（Godot 调这个）

Ken 11-26 定：先在 Mac 上跑 Python 服务，Godot 用 HTTPRequest 调（以后要跨平台再考虑 llama.cpp 嵌进游戏）。

```
.venv/bin/python scripts/serve.py            # 默认当前最好 dpo2-s1；只听 127.0.0.1:8765
GET  /health → {"ok": true, "model": ...}
POST /warm {"card": {...}} → {"seconds": ...}
POST /say  {"card": {...}, "seed": 0} → {"lines": [...] | null, "reject", "fixes", "tries", "seconds", "first_token"}
```

一次只处理一个请求。11-26 实测：curl 预读 1.1 s、生成 0.8 s（首字 0.39 s）；Godot 4.7 无界面跑客户端（游戏仓库里的
`Script/actor_client.gd`，`await client.say(card)`，4 秒超时就退回）往返 1.1 s；坏请求回 400 + 中文原因。
